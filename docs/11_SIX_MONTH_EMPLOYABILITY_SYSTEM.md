# 11 --- Six-Month Employability System

## Objective

At the end of 24 weeks, the learner should be able to independently
evaluate and apply to realistic AI/ML/Applied-AI roles, understand the
technical requirements in English, demonstrate relevant evidence, and
defend engineering decisions in interviews.

This is not a promise of eligibility for every AI job. Research
scientist, senior/staff and hard-filtered degree/language roles remain
separate opportunity classes.

## Target role lanes

### Lane A --- Production AI / Applied AI Engineer

Highest initial priority. Core: Python, APIs, backend, LLM applications,
RAG, evaluation, agents, cloud, Docker, CI/CD, observability.

### Lane B --- Machine Learning Engineer

Core: statistics, classical ML, PyTorch, data pipelines,
training/evaluation, serving, MLOps, cloud.

### Lane C --- GenAI / LLM Engineer

Core: transformers, embeddings, retrieval, reranking, RAG, evaluation,
tool use, agents, fine-tuning/PEFT, inference and LLMOps.

### Lane D --- Data Scientist

Secondary lane. Core: SQL, statistics, experimentation, classical ML,
feature engineering, communication and business analysis.

### Lane E --- MLOps / LLMOps

Specialization lane after production foundations. Core: Docker,
Kubernetes, CI/CD, MLflow, serving, monitoring, AWS, orchestration.

## 24-week capability sequence

Weeks 1--4 --- Engineering foundation - Python engineering -
Git/GitHub - Linux/shell - SQL/PostgreSQL - HTTP/REST - FastAPI -
testing - Docker basics Evidence: tested API + PostgreSQL service.

Weeks 5--8 --- ML foundation - NumPy/Pandas - probability/statistics -
train/validation/test - regression/classification - trees/ensembles -
feature engineering - leakage - metrics and imbalanced data - experiment
design Evidence: end-to-end ML service with evaluation report.

Weeks 9--12 --- Deep learning and production ML - neural
networks/backprop - PyTorch - training loops - embeddings - experiment
tracking - model packaging/serving - CI/CD - AWS foundations Evidence:
PyTorch model deployed behind API with tests and tracking.

Weeks 13--16 --- LLM engineering - transformers - tokenization/context -
embeddings - vector retrieval - RAG - chunking - reranking - structured
outputs - evaluation - guardrails/security basics Evidence:
enterprise-style RAG project with measurable retrieval/generation
evaluation.

Weeks 17--20 --- Advanced applied AI - tool calling - agents/workflows -
MCP concepts - fine-tuning - PEFT - LoRA/QLoRA - quantization -
inference trade-offs - observability - cost/latency/reliability
Evidence: agentic workflow + fine-tuning experiment with engineering
decision report.

Weeks 21--24 --- Production and hiring conversion - AWS ML/GenAI
architecture - SageMaker/Bedrock concepts mapped to MLA-C02 - Kubernetes
fundamentals - MLOps/LLMOps - system design - security - responsible
AI - portfolio hardening - mock interviews - application strategy
Evidence: flagship AI Career OS slice deployed; architecture defense;
interview benchmark.

## Parallel English track

Every week: - 3 technical listening sessions - 3 sentence-parsing
sessions - 3 short spoken explanations - 1 longer technical discussion -
1 mock interview segment - technical chunks captured from the same
weekly topic

The Turkish scaffold decreases only when comprehension tests justify it.

## Weekly readiness gates

A week is not passed because content was watched. Required: - concept
check - implementation/debugging - delayed recall - English
explanation - artifact/evidence where applicable

## Application waves

Weeks 1--8: observe market and build baseline; selective low-cost
applications for calibration. Weeks 9--16: apply to strong
junior/applied roles when critical requirements are met. Weeks 17--24:
systematic application pipeline, interview feedback loop, portfolio
variants by role.

## Certification track

AWS MLA-C02 preparation runs in parallel once ML/cloud prerequisites are
adequate. Certification study is mapped to project tasks. Vendor
certification never replaces production evidence.

Claude certification is tracked only if current access/eligibility is
available and its objectives materially overlap target jobs.

## Readiness definition

"Ready to apply" means: - no unresolved hard eligibility constraint, -
critical-skill coverage above configured threshold, - at least one
strong evidence artifact for core role skills, - can explain flagship
projects in English, - passes role-specific technical benchmark, - can
read the job description and identify architecture/trade-offs without
translation dependency.

## Stop conditions

The roadmap must not recommend: - research roles requiring
publication/PhD evidence without flagging the gap, - senior/staff roles
as realistic six-month targets solely from skill overlap, -
German-required roles without marking language as eligibility, - roles
where mandatory legal/work authorization constraints fail.
